# 第一章 项目事实

> 本章是规则的**事实基础**。发现事实错误时：先查证（§2.3），确认后改文档，再改代码；禁止在错误事实的基础上写代码。

## 1.1 一句话

STM32F405 三轴无刷相机云台固件：**电压模式 FOC + 线性霍尔测角 + IMU 姿态增稳**，裸机无 RTOS，8 kHz 控制环，串口协议受控。

## 1.2 硬件事实（已冻结，规则层面禁止建议改板）

### 1.2.1 组成

| 部件 | 型号 | 关键事实 |
|---|---|---|
| 主控板 | IUO112 | STM32F405RGT6（LQFP-64，168 MHz，1 MB Flash / 192 KB RAM，FPU 单精度），HSE 16 MHz，BOOT0 接地（只能 SWD 烧录） |
| 电机板 ×3 | BOD12-11 | 每板 1× SS6343M-QF-TP 驱动 + 2× MT9101ET 线性霍尔 |
| 驱动 | SS6343M-QF-TP | **单 PWM 每相**，内部互补 + 40 ns 死区；EN 常使能（不可单独关断）；nSLEEP 控制（唤醒 1.5 ms）；**nFAULT 悬空，故障无反馈**；**LSS 接地，无电流采样** |
| 编码器 | MT9101ET | **线性霍尔，模拟输出**（无 A/B/Z 数字信号、无霍尔中断），每轴 2 路**按 120° 机械摆放**（不是正交 90°）→ ADC → 120° 重构 → atan2 → 角度 |
| IMU | ICM-42688-P（R14AQ 板） | SPI2（8 MHz），**本项目固定用模式 3**（CPOL=1/CPHA=1），禁止写模式 0；WHO_AM_I = `0x47`；**无中断引脚**（PC6 被加热占用）；PC6 加热使能（**开关量**，滞回控制，非 PWM）；IMU 板本地 DS8242-33S3 供电（40P 只送 +7V） |
| 电源 | SY8303AAIC → 7.2 V；AMS1117-3.3 → 3.3 V | 电机、IMU 加热用 7.2 V；MCU 与霍尔用 3.3 V |
| 接口 | J3 8P 主机（USART2 + 4×PWM，PA6 用途待确认见附录 B.12）、J4 UART5 调试、40P FPC 内部总线 | — |

### 1.2.2 硬件缺陷规避清单（固件必须规避，方案见架构文档附录 B）

| # | 缺陷 | 后果与对策 |
|---|---|---|
| B1 | 无电流采样 | 只能电压模式 FOC；无力矩精确控制；不提议加电流环（需改硬件） |
| B2 | nFAULT 悬空 | 过流/过温无硬件反馈（芯片自己重启 4 ms）→ 只能间接检测（指令饱和 + 角度不跟随、母线电压、IMU 失联、MCU 温度） |
| B3 | PC0 母线采样超量程（7.2 V→3.6 V > 3.3 V 量程） | ADC 恒 4095；**只能做欠压检测**（靠电压下降沿），过压保护与前馈不可行，不要再提 |
| B9 | 只能 SWD 烧录 | 量产需治具；不要建议 UART ISP / USB DFU |
| B11 | 40P 线束与 BOD12-11 J1 顺序相反 | 1:1 直通线 = 上电即短路；排查"电机不动"先查线束 |
| B12 | PA6 复用（PWM1 输入 + Q1 基极） | 待确认输入/输出用途，配置方案见附录 B.12 |
| — | RAM 分区 | 128 KB SRAM + 64 KB CCM；**CCM（0x10000000）不能被 DMA 访问**，DMA 缓冲区（ADC/SPI/UART）绝不能放 CCM |
| — | Flash 分区 | 896 KB 代码 + 末 128 KB 参数区（`magic/version/size/CRC32`）；**两个备份槽 `0x080E0000` / `0x080F0000` 同属 sector 11，擦一次两个槽一起清，双备份当前不成立 → 待人类拍板，见第六章 Q11** |

## 1.3 软件架构事实

- **裸机，无 RTOS**（已定案，见架构文档 §4.4，不要再提议上 FreeRTOS）
- **五层**（上层可调下层，下层禁止反调；层间只走 `.h` 接口，不共享全局变量）：
  - `app`：main / fsm / mode / protocol / params / protect / thermal（100 Hz + 10 Hz）
  - `control`：pid / axis / gimbal / feedforward（8 kHz）
  - `algorithm`：hall / svpwm / imu / filter / calibration（8 kHz，纯数学，不含 HAL）
  - `driver`：pwm / adc / spi / uart / gpio / nvm / timebase（中断驱动，无业务判断）
  - `common`：board.h / config.h / types.h / stm32f4xx_hal_conf.h / math_utils / ring_buffer
- **三个频率层**：8 kHz 控制环（125 µs，ADC 中断）→ 1 kHz `protect.c`（判据/置 LATCH）→ 100 Hz `fsm.c`（迁移/nSLEEP/日志，10 ms 一拍）；IMU 采样 1 kHz（轮询，时基由定时器决定）
- PWM 载波 24 kHz（TIM1 主，ARR=6999，PSC=0），TIM1 RCR=2 使 TRGO 每 3 周期输出一次 → 8 kHz 硬件触发 ADC
- IWDG 看门狗；毫秒用 `timebase_ms()`，微秒用 `timebase_us()`
- 构建：CMake + Ninja（presets schema v3，要求 CMake ≥ 3.21）。`arm` preset 用 arm-none-eabi-gcc 交叉编译到 `build/arm`；`host` preset 在 PC 上编 `src/tests`，**由 `env.cmd` 注入的 MSVC（`vcvars64`）编译，未注入则 configure 直接报找不到 C 编译器**；测试代码需同时满足 GCC 与 MSVC 告警
- 环境：新终端先跑 `scripts\env.cmd` 注入 PATH（cmake / ninja / arm-none-eabi-gcc / openocd）
- 文档中文；`docs/`、`external/` 不入库（.gitignore 已配置，唯一例外 `external/README.md`），只提交代码

## 1.4 状态机事实（实现权威：docs/云台固件状态机设计.md §4）

- 7 状态：`S_BOOT / S_SELFTEST / S_IDLE / S_READY / S_RUN / S_CALIB / S_FAULT`；迁移 T01–T16（**T00 是复位伪状态，不是事件**；T16 是 IWDG 硬件复位，不经软件）
- 事件：32 位位掩码，**枚举顺序即优先级**；`EV_CMD_MODE` 用 `fsm_post_mode()` 带载荷
- 一拍只处理一条迁移（防止 BOOT→SELFTEST→IDLE 连跳）
- 迁移执行顺序固定：**exit → action → state → entry**；`run_armed` 最后置位
- 守卫失败也要消费事件；`params_crc_ok()` 只在 BOOT 算一次并缓存
- 标定是 `S_CALIB` **状态**，不是工作模式；`MODE_CALIB` 已删除
- LOCK/FOLLOW/RATE/RC 是 `S_RUN` 内部维度，切模式是自迁移（不跑 exit/entry）
- 降额 `derate_mask`（过温/欠压/IMU 失联，×0.7，不叠乘）由 protect.c 维护，**不是 FSM 事件，不产生迁移**
- `S_CALIB` 可被 STOP/超时（300 s）安全中止；CALIB_DONE：结果入 RAM → 断电回 IDLE → 在 IDLE 写 Flash
- 单元测试须覆盖 T01–T15 每条迁移（T16 是 IWDG 硬件复位，不写用例），见状态机文档 §10.3

# 第二章 硬规则（违反即返工）

## 2.1 安全不变量（S1–S6）

**任何代码、任何状态、任何时候不得违反；违反任何一条的代码不允许合入。**

> **S1–S6 不受文首文档优先级链约束**：若它们与任何上游文档冲突，唯一允许的动作是**停下来报告冲突**，不得按"上游优先"执行。

- **S1** 非 RUN 状态 PWM 恒 50%（三相零电压），不是 0%（0% 时桥臂状态不确定）
- **S2** 上电时序：先 PWM 50% → 再拉 nSLEEP 高；断电时序：先归 50% → 再拉 nSLEEP 低。顺序不可反
- **S3** 进 RUN 前置动作：目标角 = 当前角 → 清积分 → 最后置 `run_armed`（防使能瞬间满幅输出）
- **S4** LATCH 故障响应：8 kHz 立即 50%（≤125 µs）→ 10 ms 内 nSLEEP 低；普通 STOP 才是 10 ms 级，两者不可混
- **S5** 任何 PWM 输出必须经状态机授权的状态，禁止绕过 FSM 直接驱动电机
- **S6** FAULT 恢复必须重新自检（`S_FAULT → S_SELFTEST`），不能直接回 IDLE

## 2.2 禁止事项（P1–P15；AI 专属的 P16 见 §7.2）

- **P1** 禁止引入 RTOS、动态内存分配（malloc/free）、C++ 异常/RTTI、递归调用
- **P2** 禁止修改 `stm32/`（vendored HAL/CMSIS）、`ld/`、`CMakeLists.txt` 的工具链配置——除非任务就是改它且人类已确认
- **P3** 禁止在 `board.h` 之外硬编码引脚号、外设实例、魔数
- **P4** 禁止把 PWM 占空比设为 0%（见 S1）；非 RUN 必须 50%
- **P5** 禁止颠倒 S2 的上电/断电时序
- **P6** 禁止绕过 FSM 直接操作电机或 nSLEEP
- **P7** 禁止在控制路径阻塞；禁止在 ISR 内 `HAL_Delay`、调用不可重入函数、动态改变中断优先级
- **P8** 禁止使用 double（字面量必须带 `f`）；在 8 kHz 路径新增除法/开方/三角函数前**必须先核** `FOC技术栈.md` 的周期预算表（控制链总预算 40 µs / 32% CPU，实测约 17 µs），未核不得新增
- **P9** 禁止编造寄存器、引脚、芯片参数、库函数行为——引用时给出**出处**（文件 + 章节/页码，或仓库 + 文件路径）
- **P10** 禁止拷贝 GPL-3.0 代码（dRehmFlight / betaflight / iNav / DengFOC / 逐飞 FOC）；MIT / BSD-3 / Apache-2.0 可借鉴但必须保留原版权与许可声明（见第五章）
- **P11** 禁止一次性大改：单轮改动 ≤1 个模块；新增/修改超过 ~100 行先出接口设计等确认
- **P12** 禁止发明协议命令、状态、迁移——新命令/新迁移先提案，等 T 表扩号
- **P13** 禁止提交 `docs/`、`external/` 到 git（已 ignore）；禁止 force push、改写历史
- **P14** 禁止删除或重命名既有文件/符号，除非任务明确要求且人类确认
- **P15** 禁止在 `algorithm/`、`control/` 里 include `stm32f4xx*.h` 或直接读写寄存器——这两层必须能在 host 上编译运行（架构 §14 第 4 条）

## 2.4 高频错误对照表（本项目历史上最容易写错的点）

| # | 错误 | 正确做法 |
|---|---|---|
| 1 | `0.5`、`2.0` 等字面量是 **double** → 走软件浮点，慢 10–50 倍 | 所有浮点字面量加 `f`；一律单精度 `float`；编译 `-mfpu=fpv4-sp-d16 -mfloat-abi=hard` |
| 2 | 以为 MT9101ET 有 A/B/Z 中断 | 它是**模拟线性霍尔**，只能 ADC 采样，采样率与控制环对齐 |
| 3 | 把两路霍尔当"正交 90°" 用 `atan2(va, vb)` | 机械夹角是 **120°**，必须先 120° 重构再 atan2；只写一套解算，不做 90/120 编译期切换 |
| 4 | ICM-42688-P 用 SPI 模式 0 | **本项目固定模式 3** |
| 5 | 角度跨越 0°/360° 边界时减法出错 | 统一角度 wrap 约定（选 [0,360) 或 [-180,180)，在模块头注明），差值用带 wrap 的函数算 |
| 6 | DMA 缓冲区放 CCM RAM | CCM 不能 DMA；ADC/SPI/UART 缓冲放主 SRAM |
| 7 | 自检里检查"霍尔是否变化" | 静止时本来就不变；霍尔冻结检测只在 RUN 且 `u > 0.3` 时做，且是 LATCH 判据 |
| 8 | 在控制路径用 `HAL_Delay` | 阻塞仅允许出现在 S_BOOT 初始化和 IDLE 写 Flash（文档明确允许的场景） |
| 9 | 在 ISR 里调用不可重入函数/开全局中断 | ISR 保持短小；跨 ISR 共享数据必须 `volatile` 且考虑原子性 |
| 10 | 把"降额"写成状态迁移 | 降额只改输出幅度 ×0.7，不进 FSM |
| 11 | 无符号/有符号、`int` 隐式截断 | 用 `stdint.h` 固定宽度类型；角度用 float，计数用 `uint32_t` |
| 12 | 假设 IMU 有数据就绪中断驱动控制环 | **IMU 没有中断脚**，控制时基只能由 TIM1 TRGO 决定，IMU 只能轮询 |
| 13 | 假设 ADC 扫描下标从 M1 开始 | 下标 0/1 = M2 霍尔（PA0/PA1）、2/3 = M1（PC1/PC2）、4/5 = M3（PC4/PC5）、6 = 母线（PC0），必须按表取值 |
| 14 | 在 FAULT / 10 ms 任务里写 Flash | `nvm_save()` 只允许在 IDLE 调用（擦扇区 200 ms~1 s） |

# 第三章 开发流程

## 3.1 每个任务的七步

```
1. 读相关文档章节，列出你理解的需求与验收标准（含边界条件）
2. 给出接口设计：头文件级（函数签名、数据结构、错误码），≤1 屏
3. 接口设计经确认后实现
4. 写 host 单元测试并跑通（PowerShell 不支持 &&，用 ; 连接）
5. 交叉编译：**编译期零错误零警告**；链接期只接受 newlib nosys 桩警告（`_close/_fstat/_getpid/_isatty/_kill/_lseek/_read` 共 7 条，已知项）
6. 自查 §2.1 安全不变量与 §2.4 高频错误对照表
7. 交付（格式见 §3.4）
```

## 3.2 构建与测试命令

首次或删过 `build/` 必须先 configure，且新终端先跑 `scripts\env.cmd`：

```powershell
cmake --preset host; cmake --build --preset host; ctest --preset host
cmake --preset arm;  cmake --build --preset arm
cmake --preset arm-release;  cmake --build --preset arm-release   # 评估性能/周期预算用，Debug 是 -O0 不可用于判性能
```

## 3.3 测试覆盖要求

数学类模块（hall / svpwm / filter / imu / calibration）测试必须覆盖：正常值、**角度边界（0°、359.9°→0.1° 跨越）**、120° 重构公式的两个相位符号、NaN/Inf 输入防御、极端幅值（SVPWM 调制比 ≥1 时的 clamp）。

## 3.4 交付说明模板

每次交付必须附带以下五段（AI 写在回复里；人类的等效物是提交信息 + 评审说明）：

```markdown
## 变更
- <文件>: <函数/符号级说明>

## 验证
- host 测试: <通过 N 项 / 失败 0 项>（如实；失败就写失败）
- arm 编译: <0 error；编译期 0 warning；链接期 nosys 桩警告 N 条（已知项）>

## 风险与假设
- <我做了哪些假设；哪些行为依赖未确认的开放决策（第六章）>

## 需要你确认
- <决策点，附选项与推荐>

## 下一步
- <建议>
```

## 3.5 不确定时的决策规则

| 情形 | 动作 |
|---|---|
| 硬件事实不确定 | 查手册/原理图 → 仍不确定 → **提问**，禁止假设 |
| 方案/接口不确定 | 给 2–3 个选项 + 推荐 + 理由，等人类拍板 |
| 文档互相冲突 | 指出冲突双方出处，请求裁决 |
| 任务太大 | 拆成可编译的小步，先交付第一步 |
| 发现既有代码/文档有错 | 停下报告，确认后再改；不静默修复 |
| 需要硬件验证 | 输出《硬件验证步骤》清单（接线、期望现象、判据），交给执行者 |

# 第四章 代码风格

> **定位**：本项目同时是**学习工程**。任何进仓库的代码，假定读者是刚接触 FOC / STM32 / 本项目的新手——"能跑"不够，必须"能看懂"。
> **约束力度**：本章的"必须/禁止"类违反即返工；"建议"类不阻断合入，但偏离时需在交付说明（§3.4）的"风险与假设"里写明理由。

## 4.1 命名与文件

- C11；`snake_case`；**前缀 = 文件名**（`fsm_ / mode_ / protocol_ / params_ / protect_ / thermal_ / pid_ / axis_ / gimbal_ / feedforward_ / hall_ / svpwm_ / imu_ / filter_ / calibration_ / pwm_ / adc_ / spi_ / uart_ / gpio_ / nvm_ / timebase_`）
- 禁止自造缩写：`calib_`、`prot_`、`ff_`、`ringbuf`、`th_` 一律不写（架构 §6.2）
- include 一律从 `src/` 起算：`#include "algorithm/hall.h"`，禁止 `../../../`
- 每模块一对 `.c/.h`；头文件顶部写用法与单位约定（角度 rad/deg、时间 ms/us 必须显式）；统一 `#pragma once`
- 枚举值带模块前缀（`FSM_INIT`、`MODE_LOCK`、`AXIS_YAW`）；静态变量 `s_` 前缀；**不用全局变量**，跨模块用 getter
- 错误用返回码枚举；模块内 `static`
- 提交信息遵循仓库现状；既有文件的风格优先于本章规则

## 4.2 注释（硬性要求）

- **模块头**：每个 `.c/.h` 顶部 3~10 行——本模块干什么、给谁用、依赖谁、**谁不许调用**（层间规则写明，参照 `board.h` 的写法）
- **函数头**：每个函数（含 `static`）写清功能 / 参数**带单位** / 返回值含义 / 调用上下文（是否 ISR、8 kHz 路径、仅 IDLE 可调等）
- **步骤注释**：函数内关键块"一步一注"，写清"这一步在干什么"；初始化序列、流程步骤的行尾注释允许写"是什么"（作者要求保留此类流程注释，**禁止删除**）
- **术语**：专业词第一次出现必须解释或给出处（如 SVPWM、Park 变换 → 注明《FOC技术栈.md》§x）；禁止假设读者懂行话
- 注释优先解释"为什么"；中文；引用事实注明文档/手册章节
- **豁免**：签名自明的 trivial 函数（getter/setter、≤10 行的纯转发）可只写一行注释，不展开四要素
- **存量代码**：按"碰到即补"执行——本次任务涉及的模块必须满足本节；不要求为满足本节而单独发起全仓重写（与 P11 一致）

## 4.3 新手友好（可读性）

- **命名说人话**：变量名表达含义，建议带单位后缀（`angle_rad`、`period_ms`、`duty_pct`）；禁止单字母变量名（`i/j/k` 循环索引除外）、禁止一符多义
- **结构平直**：一个函数只做一件事，建议 ≤60 行（超了先想拆分）；嵌套 ≤3 层，用提前返回（guard clause）压平
- **一行一件事**：禁止把多个操作塞进一行；禁止嵌套三元 `?:`；禁止逗号表达式
- **位/寄存器操作**：必须逐位（逐字段）注释含义，禁止裸写
- **魔数零容忍**：数值常量一律具名（`#define`/`enum`/`const`）并注释来历——这是 P3（board.h 之外禁硬编码）在全仓库的延伸
- **测试即文档**：单元测试用例名写清被测行为（如 `hall_decode_crosses_zero_boundary`），让新手能通过读测试学会模块怎么用
- **不炫技**：可读性永远优先于简洁——"这行很聪明"不如"这行一眼懂"

# 附录 上下文速查卡

- 时钟：168 MHz；**APB1 = 42 MHz（定时器 ×2 = 84 MHz）**、**APB2 = 84 MHz（定时器 ×2 = 168 MHz）**
- PWM：24 kHz，TIM1 主（ARR=6999，PSC=0，RCR=2 → TRGO 8 kHz）；M1 = TIM4（CH3/CH2/CH1，倒序）、M2 = TIM1（CH1/CH2/CH3）、M3 = TIM3（CH4/CH3/CH2）；控制环 8 kHz（125 µs）
- ADC 扫描下标：0/1 = M2 霍尔（PA0/PA1）、2/3 = M1 霍尔（PC1/PC2）、4/5 = M3 霍尔（PC4/PC5）、6 = 母线（PC0，超量程，仅欠压）
- nSLEEP：PC10 = 电机1、PA11 = 电机2、PA12 = 电机3
- SPI2 = IMU（PB12 CS 软件控制）；USART2 = 主机（PA2/PA3）；UART5 = 调试遥测（PC12/PD2）；PC6 = IMU 加热；PC11 = Q1 监测
- 参数区：Flash 末 128 KB（槽 A `0x080E0000`、槽 B `0x080F0000`，同扇区问题见第六章 Q11）
- 三个频率层与端到端延迟：LATCH 故障 ≈1.125 ms 归零（1 ms 检测 + 125 µs 响应）；普通 STOP ≈10 ms
