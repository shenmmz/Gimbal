# Gimbal · 无人机三轴相机云台固件

基于 STM32F405 的裸机嵌入式固件，用于驱动三轴 BLDC 无刷电机云台（Yaw / Pitch / Roll）。

## 项目概述

本项目实现了一个高性能的三轴云台控制系统，具有以下技术特点：

- **控制架构**：电压模式 FOC（磁场定向控制），8 kHz 控制环频率
- **驱动方式**：24 kHz PWM，三相桥式驱动
- **位置反馈**：线性霍尔传感器直接输出绝对角度，无需编码器
- **IMU 融合**：ICM-42688-P 六轴 IMU 提供姿态参考和抗扰辅助
- **实时性能**：单周期控制延迟 ≤125 µs，全栈响应时间 <10 ms
- **保护机制**：多层故障检测（过温、欠压、堵转、霍尔失效）与自动恢复

### 技术规格

| 项目 | 参数 |
|---|---|
| MCU | STM32F405RGT6 @ 168 MHz (Cortex-M4F) |
| 存储占用 | Flash 23,152 B (2.52%) · RAM 6,032 B (4.60%) |
| 控制频率 | 8 kHz (125 µs 周期) |
| PWM 频率 | 24 kHz |
| 电机驱动 | 3× SS6343M (16V/2A 持续) |
| 位置反馈 | 6× MT9101ET 线性霍尔 (每轴 2 颗) |
| IMU | ICM-42688-P (SPI 接口) |
| 通信接口 | UART2 (主机) + UART5 (调试) |
| 电源输入 | VDD (7.2V 经过 SY8303 降压) |

## 硬件组成

系统由四块 PCB 组成，通过 40P FPC 扁平线缆连接：

| 板卡 | 型号 | 数量 | 核心器件 | 功能 |
|---|---|---|---|---|
| 主控板 | IUO112 | 1 | STM32F405RGT6 + 3× SS6343M | 主控 MCU、三路电机驱动、电源管理、对外接口 |
| 电机端板 | BOD12-11 | 3 | 2× MT9101ET 线性霍尔 | 位置检测、电机三相接口 |
| IMU 板 | R14AQ | 1 | ICM-42688-P + DS8242-33S3 | 六轴 IMU、加热恒温控制 |
| 内部总线 | 40P FPC | — | DF56C-40S-0.3V(51) | 主板到四块子板的唯一信号/电源通道 |

### 硬件约束

硬件设计已冻结，以下限制直接决定了固件实现方式，不可绕开：

| 硬件事实 | 固件后果 |
|---|---|
| 无相电流采样（LSS 直接接地） | 只能做**电压模式 FOC**，没有电流环，动态性能受限 |
| 霍尔输出模拟电压（绝对角） | 上电即知转子位置，**不需要预定位 / 开环强拖**，状态机大幅简化 |
| 3 路 nFAULT 悬空 | 过流/过温后芯片自恢复 4 ms，MCU 无感知，保护只能靠"指令饱和 + 角度不跟随"判堵转 |
| 母线分压 1:2 超量程（7.2 V → 3.6 V > 3.3 V） | 测不到工作点电压，前馈用固定常量，该通道只做欠压判别（<6.6 V） |
| IMU 的 INT1/INT2 悬空 | 只能轮询读取 IMU，**控制时基必须由定时器决定**，不能靠数据就绪中断触发 |
| 三轴 PWM 通道顺序各不相同 | 必须**表驱动**（M1 倒序 TIM4_CH3/2/1，M2 正序 TIM1_CH1/2/3，M3 TIM3_CH4/3/2），不能假设顺序一致 |
| EN 全部上拉到 3.3V | 只能整片 nSLEEP 控制，不能单相关断 |
| 加热栅极仅 1.65 V | 加热 PI 输出直接给满，不做精细占空比调节 |

> 详细硬件设计见《硬件设计总结》和《IUO112_引脚配置清单》。

## 快速开始

### 环境要求

- **操作系统**：Windows 10/11
- **编译工具**：Visual Studio 2019/2022（提供 CMake 和 Ninja）
- **交叉编译工具链**：Arm GNU Toolchain（自动下载，约 323 MB）
- **调试工具**：ST-Link + OpenOCD

### 安装步骤

```bat
:: 1) 安装工具链（一次性操作，约 323 MB）
scripts\setup-toolchain.cmd

:: 2) 每次打开新终端时，先注入环境变量
scripts\env.cmd

:: 3) 编译固件
cmake --preset arm
cmake --build --preset arm

:: 4) 运行 PC 端单元测试（算法层不依赖硬件）
cmake --preset host && cmake --build --preset host && ctest --preset host

:: 5) 烧录到开发板（需要 ST-Link）
openocd -f interface/stlink.cfg -c "transport select swd" -f target/stm32f4x.cfg ^
        -c "program build/arm/gimbal.elf verify reset exit"
```

### 编译产物

编译后的文件位于 `build/arm/` 目录：

| 文件 | 说明 |
|---|---|
| `gimbal.elf` | ELF 格式可执行文件（含调试符号） |
| `gimbal.bin` | 二进制固件（烧录用） |
| `gimbal.hex` | Intel HEX 格式固件 |
| `gimbal.map` | 链接映射文件（内存布局分析） |

当前资源占用：
- **Flash**: 23,152 B (2.52% of 1 MB)
- **RAM**: 6,032 B (4.60% of 192 KB)

## 工作模式

云台支持以下工作模式，可在运行时切换：

| 模式 | 说明 | 目标角来源 |
|---|---|---|
| LOCK | 锁定模式 | 进入时的当前角，保持不动 |
| FOLLOW | 跟随模式 | 上位机 `SET_ANGLE` 命令 |
| RATE | 速率模式 | 上位机 `SET_RATE` 命令积分 |
| RC | 遥控模式 | PWM1–4 输入信号 |

模式切换通过 `SET_MODE` 命令实现，切换过程中目标角会平滑过渡，避免云台抖动。

## 故障保护

系统实现多层故障检测与保护机制：

### 故障分级

| 故障类型 | 判据 | 级别 | 恢复方式 |
|---|---|---|---|
| 堵转 | 电压 > 0.9 且角度误差 > 5° 持续 200 ms | **LATCH**（锁死） | 人工清除 + 重新自检 |
| 霍尔超量程 | 霍尔原始值 ∉ [200, 3900] | **LATCH** | 人工清除 + 重新自检 |
| 霍尔冻结 | 运行中霍尔值 100 ms 不变 | **LATCH** | 人工清除 + 重新自检 |
| MCU 过温 | 内部温度 > 85 °C | DERATE（降额） | 自动恢复（<80 °C） |
| 母线欠压 | Vbus < 6.0 V | DERATE | 自动恢复（>6.3 V） |
| IMU 失联 | WHO_AM_I ≠ 0x47 或连续超时 | DERATE | 自动恢复（通信恢复 100 ms） |

### 三层响应

```
8 kHz 控制环（ADC 中断）           ← 125 µs，真正决定输出
    if (protect_latched() || !fsm_is_running()) {
        duty = 0.5f;                ← 立即零电压，不等任何人
    }

1 kHz protect_step()                ← 1 ms，检测
    判据成立 → 置 g_fault_flags → fsm_post(EV_FAULT_RAISE)

100 Hz fsm_step()                   ← 10 ms，只做记录与恢复策略
    看到事件 → 迁到 S_FAULT → 拉低 nSLEEP → 写故障日志
```

## 常见问题

### Q: 为什么使用电压模式 FOC 而不是电流模式？

A: 硬件设计将 SS6343M 的 LSS 引脚直接接地，没有相电流采样电阻，因此无法实现电流环。只能采用电压模式 FOC，靠反电动势前馈补偿动态性能。

### Q: 为什么 IMU 用轮询而不是中断？

A: IMU 板的 INT1/INT2 引脚悬空，未连接到 MCU。因此只能通过定时器触发轮询读取 IMU 数据，控制时基由定时器决定。

### Q: 如何调试控制环？

A: 通过 UART5 调试串口输出实时数据（角度、速度、PWM 占空比等），配合逻辑分析仪或示波器观察波形。详见《开发环境链路》。

### Q: 如何修改控制参数？

A: 通过 UART2 协议发送 `SET_PARAM` 命令修改参数，或直接修改代码中的默认值。参数保存在 Flash 末尾 128 KB 区域，掉电不丢失。
